## 1. Project Overview

FourthWave is a creative technology company focused on building digital products and providing digital services.

The company combines several areas of expertise:

1. Web Development
2. Mobile Development
3. Video Editing
4. Product / Digital Sales

The FourthWave website will be a single-page, visually impressive company website designed primarily to communicate the company's capabilities, personality, work, and quality.

The website should feel modern, creative, premium, and technologically capable.

The primary goal is not to provide complex functionality. The primary goal is to create a strong visual experience that represents FourthWave as a modern technology and creative team.

---

## 2. Website Goals

The website should:

- Present FourthWave as a professional technology and creative company.
- Clearly communicate what FourthWave does.
- Showcase the company's four main areas of expertise.
- Present selected projects that FourthWave is proud of.
- Introduce the people/team behind FourthWave.
- Create a strong first impression.
- Encourage potential clients or partners to make contact.
- Feel modern and memorable rather than like a generic corporate website.
- Use animation and interaction to enhance the experience.
- Work exceptionally well on both desktop and mobile devices.

The website should prioritize:

**Visual quality → User experience → Content clarity → Performance → Functionality**

## 16. Responsive Design

The website must be fully responsive.

It should provide a high-quality experience on:

- Large desktop screens
- Standard desktop/laptop screens
- Tablets
- Mobile phones

The four-square "What We Do" section should be specifically designed for mobile rather than simply shrinking the desktop layout.

The mobile version may use:

- Stacked sections.
- Horizontal interactions.
- Simplified animations.
- Different spacing.
- Alternative compositions.

Responsive behavior should prioritize usability over maintaining the exact desktop layout.

---

## 17. Performance

Although the website is visually focused, performance is important.

The implementation should:

- Optimize images.
- Avoid unnecessarily large assets.
- Lazy-load heavy media where appropriate.
- Avoid excessive JavaScript.
- Avoid unnecessary dependencies.
- Respect reduced-motion preferences.
- Keep animations smooth.
- Avoid blocking the initial page load.

Large videos should not automatically load at full resolution if they are not immediately required.

---

## 18. Accessibility

The website should follow reasonable accessibility practices.

At minimum:

- Semantic HTML.
- Keyboard-accessible interactive elements.
- Accessible buttons and links.
- Meaningful alt text for images.
- Sufficient text contrast.
- Proper heading hierarchy.
- Form labels.
- Reduced-motion support.

Visual design should never completely override usability.

## 22. Development Rules

The following rules should be followed during development.

### Rule 1 — Documentation First

Important project decisions should be documented.

### Rule 2 — Do Not Invent Requirements

If information is missing, mark it as `To Be Defined` instead of inventing business information.

### Rule 3 — Reusable Components

Create reusable components where there is a clear benefit.

Avoid both extremes:

- One huge component containing the entire website.
- Excessive abstraction for simple elements.

### Rule 4 — Avoid Unnecessary Dependencies

Do not install libraries simply because they are popular.

Every major dependency should have a clear purpose.

### Rule 5 — Responsive by Default

Every section should be designed with mobile and desktop in mind.

### Rule 6 — Animation With Purpose

Animations should improve the experience.

Do not add animations simply because they are technically possible.

### Rule 7 — Do Not Modify Unrelated Files

When working on a specific feature or section, avoid modifying unrelated parts of the application.

### Rule 8 — Preserve Existing Decisions

Before making architectural or visual changes, check the relevant files inside `/docs`.

### Rule 9 — Keep the Code Maintainable

Prefer:

- Clear naming.
- Small focused components.
- Type safety.
- Consistent formatting.
- Simple solutions.

### Rule 10 — Discuss Major Changes

Do not make major architectural, dependency, or design changes without discussing them first.

## 24. AI Development Guidelines

AI coding assistants may be used extensively during development.

Before making changes, the AI should:

1. Inspect the existing project.
2. Read relevant documentation.
3. Understand the existing architecture.
4. Avoid changing unrelated code.
5. Follow documented design decisions.
6. Ask for clarification when requirements are genuinely unclear.
7. Avoid inventing company information.
8. Prefer incremental implementation.

AI should not rebuild the entire project when only a single component needs modification.
